# AI 短剧应用 MVP 产品需求

版本：0.2（账号、互动与管理员权限）  
目标：交付可在浏览器运行、后续可通过 WebView 嵌入 App 的登录刷剧闭环，以及按角色授权的内容与互动管理后台。

> 本文定义本轮验收目标。页面、接口和 SQL 是否已完成，应以实际运行和测试结果为准。

## 1. 产品范围

本轮面向注册用户提供登录后刷剧、选集、评论和弹幕；面向管理员提供剧目维护、发布和互动审核。数据保存到本地 MySQL，演示视频通过需要登录的媒体接口访问。“AI 短剧”仍是内容定位，首版不包含脚本或视频生成模型。

| 优先级 | 范围 | 验收结果 |
| --- | --- | --- |
| P0 | 注册、登录、退出、会话恢复 | 用户登录后可访问内容；退出或 Session 失效后回到登录入口。 |
| P0 | H5 推荐流、详情、选集和受保护媒体 | 已登录用户可观看已发布剧目，未登录请求被拒绝。 |
| P0 | 评论与弹幕 | 用户可发评论和指定分集弹幕；刷新后数据仍存在。 |
| P0 | 管理员内容管理 | 只有 `ADMIN` 可新建、编辑、发布、撤回和删除剧目。 |
| P0 | 互动审核 | 管理员可隐藏、恢复和永久删除评论/弹幕。 |
| P0 | MySQL 初始化 | 可用 `shortdrama-backend/sql/001_init_mysql.sql` 在 Navicat 或 MySQL CLI 初始化 `yingke_drama`。 |
| 后续 | AI 生成、付费权益、推荐算法、生产媒体链路、细分运营角色 | 另立需求和接口。 |

## 2. 用户与权限

| 角色 | 权限 |
| --- | --- |
| 未登录用户 | 注册、登录、获取完成认证流程所需的 CSRF Token；不可浏览剧目、读取互动或获取演示媒体。 |
| 普通用户 `USER` | 浏览已发布剧目、播放媒体、查看和发表可见评论/弹幕、退出登录。 |
| 管理员 `ADMIN` | 包含普通用户能力；管理全部剧目，查看全部互动，隐藏、恢复或删除互动。 |

注册只能获得 `USER` 角色。角色判断必须由服务端完成；隐藏按钮、修改前端状态或直接拼接管理 URL 均不能取得管理员权限。普通用户请求管理接口应得到权限错误且数据不发生变化。

## 3. 核心用户路径

1. 新用户打开 H5，进入登录/注册页。注册时填写用户名、昵称和密码；注册成功后已建立登录会话并进入内容页。已有用户直接登录。
2. 页面刷新时调用当前用户接口恢复 Session。Session 无效时清理本地用户展示状态并返回登录页，不能继续显示受保护内容。
3. 已登录用户进入推荐流，浏览并播放已发布剧目；打开详情后按顺序选集。媒体请求也携带登录会话。
4. 用户在剧目下发表评论，或在当前分集与播放时间点发送弹幕。发布成功后互动进入可见列表；失败时保留输入并给出明确原因。
5. 管理员进入后台维护草稿与已发布剧目。普通用户无后台入口，直接访问后台路由也会因服务端权限校验失败。
6. 管理员在互动审核页查看评论和弹幕，将不合适内容隐藏；隐藏记录可恢复。永久删除需二次确认，删除后不可在产品内恢复。
7. 用户退出后 Session 失效，内容、互动和演示媒体接口不再可访问。

## 4. 页面与交互

### 4.1 登录与注册

| 页面/状态 | 必需内容 |
| --- | --- |
| 登录 | 用户名、密码、提交、切换注册；包含提交中、凭据错误、网络失败状态。 |
| 注册 | 用户名、昵称、密码、确认密码；包含必填、格式、两次密码不一致和用户名冲突提示。 |
| 会话恢复 | 页面启动时显示稳定的加载状态；成功进入内容，失败进入登录，不闪现管理页面。 |

密码输入默认遮挡，错误提示不泄露多余账号信息。前端不保存明文密码。所有写操作按后端返回的 `headerName` 携带 CSRF Token；Token 失效时可刷新一次并提示用户重试，不能静默无限重放请求。

### 4.2 H5 刷剧与互动

| 页面 | 必需内容与操作 | 关键状态 |
| --- | --- | --- |
| 刷剧首页 | 全屏竖屏视频、剧名/集数、播放/暂停、静音、详情、选集、评论、弹幕入口 | 首次加载、播放中、暂停、缓冲、失败、无内容、会话失效 |
| 剧目详情/选集 | 封面、标题、简介、类型、有序分集、当前集高亮 | 加载中、空剧集、接口失败 |
| 评论区 | 可见评论列表、作者昵称、内容、发布时间、发布输入 | 空态、发布中、发布失败、内容被隐藏后的刷新状态 |
| 弹幕 | 当前分集的可见弹幕、开关、文本输入 | 无弹幕、发送失败、过密时的轨道处理 |

评论可属于整部剧，分集 ID 可省略。弹幕必须属于一个分集，并携带播放时间 `at` 和轨道 `lane`；界面应限制文本长度、空白内容和非法时间值，但服务端仍需重复校验。用户输入按纯文本展示，不能作为 HTML 执行。后台隐藏或删除互动后，用户刷新或重新拉取时不再看到该内容。

移动端以 320–430px 为主要宽度，适配刘海屏和底部手势区。详情或评论层打开时暂停视频或保持清晰的播放状态；弹幕不得遮住主要播放控件、剧名和系统安全区。浏览器阻止自动播放时显示明确的播放按钮。

### 4.3 管理后台

| 页面 | 必需内容与操作 | 关键状态 |
| --- | --- | --- |
| 内容列表 | 标题、封面、状态、集数；新建、编辑、预览、发布/撤回、删除 | 无权限、空列表、加载失败、操作反馈 |
| 剧目编辑 | 标题、简介、类型、封面、状态及完整分集数组 | 校验错误、未保存更改、保存失败 |
| 基础概览 | 剧目总数、已发布数、分集总数 | 无数据时显示 0 和统计口径 |
| 互动审核 | 评论/弹幕、作者、剧目/分集、状态；筛选、隐藏、恢复、删除 | 空列表、加载失败、状态更新冲突 |

隐藏是可逆审核操作：记录状态从 `VISIBLE` 改为 `HIDDEN`；恢复改回 `VISIBLE`。删除是永久操作，需二次确认并明确不可恢复。审核列表应能区分评论与弹幕，并显示弹幕对应分集及时间点。管理员不能仅依靠前端过滤判断权限。

## 5. 内容与互动规则

| 对象 | 字段 | 规则 |
| --- | --- | --- |
| 用户 | ID、用户名、昵称、角色 | 用户名唯一；普通注册不能指定角色。 |
| 剧目 | ID、标题、简介、类型、封面 URL、状态、分集数组 | `DRAFT`、`PUBLISHED`；普通用户只见已发布内容。 |
| 分集 | ID、标题、视频 URL、时长秒数、免费标记 | 顺序等于后台数组顺序，随剧目整体管理。 |
| 互动 | ID、类型、文本、剧目、可选分集、时间点、轨道、作者、状态 | 类型为 `COMMENT`、`DANMAKU`；状态为 `VISIBLE`、`HIDDEN`。 |

剧目 `PUT` 仍提交完整分集数组，保存前提醒未提交的旧分集及相关互动会被删除。删除剧目时级联删除其分集和全部互动；删除分集时级联删除该分集互动。MySQL 外键采用 `ON DELETE CASCADE`；整体替换分集时的服务层清理路径仍需通过实现测试确认，不能留下孤立互动。

评论的分集可空；弹幕的分集必填且必须属于当前剧目。互动作者来自当前登录用户，前端不能代填他人身份。普通用户读取互动时必须传 `type`，可用 `episodeId` 筛选；只返回 `VISIBLE`。管理员可按 `type` 和 `status` 筛选全部互动。

## 6. 安全与异常验收

- 未登录访问剧目、互动、演示媒体和管理接口时不能获得业务数据。
- `USER` 直接调用内容管理或互动审核接口时返回 `403`，且数据库无变化。
- 缺少或伪造 CSRF Token 的写请求被拒绝；携带当前 Session 与正确 Token 的合法写请求可继续。
- 登录失败、重复用户名、表单校验失败、Session 过期和网络错误均有明确反馈，不出现无限加载。
- 普通用户无法通过注册请求、修改响应或篡改前端状态获得 `ADMIN`。
- 评论和弹幕中的 HTML/脚本内容以文本显示，不执行脚本。
- 弹幕引用其他剧目的分集、非法时间点或缺失分集时创建失败。
- 隐藏互动后普通列表不可见，恢复后重新可见，删除后后台和普通列表均不可见。
- 演示媒体仅允许 `drama-1.mp4` 至 `drama-4.mp4`，拒绝路径穿越，支持 Range；退出后旧会话不能继续获取媒体。

## 7. 本地 MySQL 与 Navicat 验收

开发者使用 `shortdrama-backend/sql/001_init_mysql.sql` 初始化本地 MySQL 数据库 `yingke_drama`。Navicat 操作流程为：连接本地 MySQL，创建或选择 `yingke_drama`，打开该 SQL 文件，确认执行目标后运行；也可使用 MySQL CLI 完成同一操作。连接环境变量和应用启动命令以 README 与实际配置为准。

数据库账号使用最小必要权限，连接密码不提交到仓库。验收至少覆盖：脚本能在目标环境执行；服务重启后用户、剧目、评论、弹幕和隐藏状态保留；唯一用户名与外键/索引约束生效；初始管理员凭据通过受控方式提供并要求生产环境更换。

Navicat 是可选的数据库管理客户端，不属于应用运行依赖。

## 8. 后续范围

- AI 生成：脚本、分镜、视频生成任务、费用、重试、产物审核与版权来源。
- 生产媒体：对象存储、转码、CDN、短时签名地址、防盗链和播放权益。
- 精细运营：角色分级、审核日志、禁言、举报、敏感词策略和互动申诉。
- 商业化：付费剧集、订单、支付回调、退款及服务端权益校验。
- 原生 App：WebView Cookie 与 CSRF 适配，分享、推送、支付等版本化 Bridge。

## 9. 本轮交付判定

在本地 MySQL 环境完成端到端验证：新用户可注册登录，刷新后恢复会话；登录用户可浏览已发布剧目、播放受保护演示媒体、发表评论和分集弹幕；普通用户不能进入管理接口；管理员可维护剧目，并隐藏、恢复、删除互动；退出后受保护内容不可访问；CSRF、权限与持久化测试覆盖上述关键路径。任何未通过运行或测试确认的能力应在交付说明中列为待验证，而不是标记为完成。
