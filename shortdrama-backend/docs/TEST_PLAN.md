状态：第 13 节本地增量验收已执行通过，记录见第 14 节；真实穿山甲与微信/支付宝渠道仍待凭据和真机/沙箱联调。第 1～12 节保留为基础功能清单和历史执行证据。API 具体请求字段以最终接口契约为准。P0 任一项失败即不通过本版验收。

## 1. 验收准备

- 启动 Java API 和 H5/管理端，记录访问地址及版本；使用独立测试库，避免修改演示或生产数据。管理页面仅在可信本地环境访问，另开游客浏览器会话检查公开接口。
- 准备一部合法授权的测试剧目、3 集浏览器可播放的竖屏视频、封面，以及一条必定失效的媒体 URL。若缺少可播放素材，端到端播放验收标为阻塞，不能把封面显示当作通过。
- 至少覆盖桌面管理端、手机浏览器 320px/375px/430px 宽度。移动端至少各测一次 iOS Safari 或 WKWebView、Android Chrome 或 Android WebView；记录系统和浏览器版本。
- 每个接口检查响应状态、JSON 字段、数据隔离和实际 UI 结果；打开浏览器控制台和网络面板，确认没有导致流程中断的错误。

## 2. P0 API 与权限

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| API-01 | 调用 `GET /api/dramas` 和 `GET /api/dramas/{id}`；创建一部草稿后重试 | 公开接口仅返回 `PUBLISHED` 剧目；草稿不出现在列表，直接访问草稿详情返回 `404`。 |
| API-02 | 在本地可信环境请求 `GET /api/admin/dramas` 和 `GET /api/admin/overview` | 列表包含草稿和已发布内容；概览字段与实际数据一致，空库显示 0。接口无登录是首版已知边界。 |
| API-03 | `POST /api/admin/dramas` 创建草稿，含 3 集；修改标题、顺序、视频 URL 后 `PUT /api/admin/dramas/{id}`，刷新后台并重启 Java 服务 | 数据、剧集数组顺序、状态与服务端 ID 保持一致；已有集带 ID 更新，新集不带 ID 创建，不产生重复记录。 |
| API-04 | 提交空标题、非法状态、负数时长、无效字段和不存在的 ID | 参数错误返回 `400`、不存在返回 `404`；错误不泄露数据库细节，失败后原数据不被部分覆盖。具体约束以最终字段校验为准。 |
| API-05 | 将草稿剧目更新为 `PUBLISHED`，使用真实媒体播放；再改回 `DRAFT` | 发布后游客可见，改回草稿后游客新请求不可见；返回剧集顺序与后台保存顺序一致。失效媒体在 H5 显示错误状态。 |
| API-06 | 更新时省略数组中的一集，确认管理端提示后提交；再删除剧目 | 服务端数组与最终提交一致；被移除分集和被删剧目的子记录均不残留，公开详情返回 `404`。 |
| API-07 | 向公开路径发送修改请求、请求未知 ID，并检查异常响应 | 公开路径没有修改能力；未知 ID 有明确 4xx；响应不含数据库凭据或堆栈。 |
| API-08 | 重复请求包含多部已发布剧目的列表和单部详情 | 结果完整且顺序稳定；同剧目的分集与保存的数组顺序一致，无重复或不存在的下一集。 |

## 11. 账户、服务端互动与 MySQL 增量验收

### 11.1 当前契约与测试数据

- 角色为 `USER`、`ADMIN`。未登录仅允许访问 `GET /api/auth/csrf`、`POST /api/auth/register`、`POST /api/auth/login`；剧目、互动、媒体均需登录，`/api/admin/**` 仅允许 `ADMIN`。
- 写请求先用同一会话调用 `GET /api/auth/csrf`，保留 `JSESSIONID`，并按响应中的 `headerName` 携带 token。不得把固定 token、管理员凭据或角色判断硬编码在前端。
- 准备普通账号 A、普通账号 B、管理员账号，一部已发布且含至少 2 集的剧目，以及每集各 1 条 `COMMENT`、`DANMAKU`。文本包含中文、空格、HTML 特殊字符和 emoji，用于持久化、隔离和转义验证。
- MySQL 验收使用独立本地库；先在 Navicat 导入 `shortdrama-backend/sql/001_init_mysql.sql`，再配置 `MYSQL_PASSWORD`、`YINGKE_ADMIN_PASSWORD` 等环境变量并以 `--spring.profiles.active=mysql` 启动。不得使用现有业务库执行删除测试。

### 11.2 P0 身份、会话与 CSRF API

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| AUTH-01 | 新会话调用 `/api/auth/csrf`，记录 Cookie、token、`headerName`；不带 token、带错误 token、使用另一会话 token 分别提交注册或登录 | CSRF 响应可用；所有无效写请求被 `403` 拒绝且不产生账号/会话；同一会话正确 token 可继续。 |
| AUTH-02 | 用有效数据注册 A；重复用户名、空白用户名、弱/空密码、超长字段和多余角色字段分别注册 | A 创建成功且默认只能是 `USER`；非法请求为明确 4xx，不生成重复账号；客户端不能通过请求把自己注册为 `ADMIN`。 |
| AUTH-03 | 使用错误密码和正确密码登录 A，再调用 `/api/auth/me` | 错误凭据返回 `401` 或契约约定的 4xx 且不建立登录态；正确登录后 `me` 只返回必要的账号标识与 `USER` 角色，不返回密码哈希。 |
| AUTH-04 | 登录 A 后携带原 CSRF token 写互动；再重新获取 token 重试 | 登录导致会话或 CSRF token 更新时，旧 token 被拒绝并可通过重新取 token 恢复；前端不能因 token 轮换永久卡死。 |
| AUTH-05 | 登录后调用 `/api/auth/logout`（带正确 CSRF），随后访问 `me`、剧目、互动和媒体；重放旧 Cookie | 退出成功并使服务端会话失效；后续均为 `401`，旧会话不能重放。 |
| AUTH-06 | 未登录访问 `/api/dramas`、详情、互动和 `/api/media/demo/drama-1.mp4` | 全部返回 `401`；响应不泄露内容、互动数据、媒体字节或本地文件路径。 |
| AUTH-07 | A 访问每个 `/api/admin/**` 读取及写接口；管理员执行同样请求 | 普通用户统一 `403` 且数据不变；管理员在有效会话与 CSRF 条件下成功。未登录为 `401`，不能混成 `403`。 |
| AUTH-08 | 登录 A 与 B，尝试在互动请求中伪造作者、用户 ID、角色、状态；检查错误响应和日志 | 作者和角色只取服务端会话；普通用户不能创建 `HIDDEN`、冒充他人或提权；响应/日志无密码、哈希、Cookie、CSRF token 和数据库凭据。 |

### 11.3 P0 受保护剧目与媒体

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| MEDIA-01 | A 登录后请求剧目列表和详情，检查每集 `videoUrl`，再实际播放 | 只返回 `PUBLISHED`；视频 URL 指向受保护的 `/api/media/demo/drama-N.mp4`，浏览器携带会话后可以播放，不绕过到公开 `/demo/*.mp4`。 |

### 13.6 素材上传、元数据与失败清理

### 13.8 自动化、数据隔离与发布判定

- 后端集成测试必须开启 Spring Security，覆盖历史/收藏唯一约束、last-write-wins、95%完成、唯一 view 并发、会员边界时间、授权撤销后 Range `403`、旧 demo 仅 ADMIN、上传签名/限额/失败清理。
- Flyway 必须在两个真实 MySQL 临时库执行：旧 5 表/29 字段库验证 baseline `1` 后执行 V2→V6，空库验证 V1→V6；各自重复启动并比较 schema、`flyway_schema_history`、旧数据行数与关键哈希。H2 单测不能替代迁移验收。
- Playwright 使用 A/B/ADMIN 与 A 的第二设备四个 context，覆盖进度跨设备、收藏隔离、权益即时变化、锁集直链、自动连播、快速手势取消和上传 UI；网络面板断言锁集未发媒体请求。
- 上传测试为每个请求记录临时目录、最终文件和 asset 行基线/结果；清理只删除本轮 `qa_next_` 数据和对应 UUID 文件，不使用目录级删除。
- 阻断条件：迁移丢失/重置旧数据或重复启动失败；A 可读写 B 历史/收藏/权益；锁集能通过任意媒体/Range/asset 路径取得字节；会员过期/撤销后新请求仍可播放；唯一 view 可刷量；上传失败留文件或孤儿行；进度不跨设备；自动连播绕过锁定；长按结束不恢复原倍速。

### 13.9 穿山甲激励广告与单集授权

本期仅接入穿山甲直客激励视频，不按 GroMore 回调验签。Android/iOS 分别配置 `appId/placementId/SecurityKey/rewardName/rewardAmount`，总开关与双端开关默认关闭。正式 AppID、广告位和 SecurityKey 未提供前只能完成服务端接口与模拟回调测试，不能宣称真实广告已上线。

接口：`GET /api/rewards/csj/config` 仅返回总开关、Android/iOS 的配置状态及客户端初始化所需 AppID/广告位，绝不返回 SecurityKey；`POST /api/rewards/csj/attempts` body `{episodeId,platform:ANDROID|IOS}` 创建短时 attempt，并返回服务器生成的 `providerUserId`、一次性 `extra` 与 `expiresAt`；`GET /api/rewards/csj/attempts/{id}` 仅本人可查。公开 `GET /api/rewards/csj/callback` 接收官方参数 `user_id,trans_id,reward_name,reward_amount,extra,sign`，签名算法为 `sha256(SecurityKey:trans_id)`，只在服务端完整校验后授予单集权益，固定响应 `{"isValid":true|false}`。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| CSJ-01 | 默认配置下读取能力并创建 Android/iOS attempt | config 明确 `enabled=false`、两端未配置且不含 secret/SecurityKey；创建返回可诊断 4xx/503，不产生 attempt 或权益。 |
| CSJ-02 | 分别只配置 Android、只配置 iOS，再启用对应端 | config 仅对应端 `configured/enabled`；未配置端不能创建 attempt。返回的 appId/placementId 与端匹配且没有另一端或服务端密钥泄漏。 |
| CSJ-03 | A 为已发布锁集创建 attempt | attempt 绑定 A、episode、platform、预期奖励和服务器 nonce，返回 `PENDING`、`providerUserId`、一次性 `extra`、未来 expiresAt；免费集、草稿集、未知集、已有权益集不创建有效 attempt。 |
| CSJ-04 | B/匿名查询 A 的 attempt，A 查询未知 attempt | 不暴露存在性或用户/nonce/交易详情；仅 A 能看到本人状态，客户端无接口可直接把状态改为成功。 |

| CSJ-08 | 将已成功 trans_id 用于另一 attempt、另一用户或另一端，或将 nonce 与 user_id 交叉组合 | 返回 invalid；交易 ID 唯一约束与业务校验同时阻止跨 attempt/跨用户领奖，原成功记录和权益不变。 |

| CSJ-10 | 缺/错 CSRF 创建 attempt、普通用户伪造平台/episode/用户字段、对 callback 使用 POST 或多余参数 | 写接口安全策略不降级；attempt 用户只取登录会话；回调只接受冻结方法和字段，未知字段不改变授权目标。 |

| CSJ-12 | 原生 bridge 报成功后轮询 attempt；浏览器直接访问 H5 | App 内仅在服务端回调成功后轮询到 `GRANTED` 并解锁；回调延迟时保持等待/可重试，浏览器明确提示需在 App 内使用且不能本地伪造成功。 |
